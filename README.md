# Offer bot

Бот отвечает текстом оффера на исходящее сообщение владельца подключённого Telegram Business-аккаунта. В сообщении должны быть ссылка NFT, язык и цена, например `https://t.me/nft/AbCdEf ru 10 rub` или `https://t.me/nft/AbCdEf en 100 stars`. Если язык не указан, используется русский. Поддерживаются `gram`, `stars` и `rub`.

Шаблоны оферов находятся в [data/offer_template.txt](data/offer_template.txt) и [data/offer_template_en.txt](data/offer_template_en.txt). В них доступны `{user}`, `{link}` и `{price}`.

## Бесплатный доступ и контроль оферов

Бесплатное использование можно ограничить участием в вашей группе. Укажите ссылку на неё в `REQUIRED_GROUP_LINK`, добавьте бота в группу и выдайте ему права администратора для проверки членства. В личном чате пользователь вступает в группу и нажимает «Я вступил(а), проверить». Членство проверяется при запуске и перед отправкой офера. Для корректной проверки боту нужны права администратора в группе. Идентификатор группы хранится в `data/business_bot.sqlite3`.

Каждый отправленный офер появляется у администратора как карточка-лот. Карточка обновляется при принятии, отклонении или подтверждении передачи NFT. Команда `/stats` показывает сводку.

Роли и списки доверенных аккаунтов задаются переменными `ADMIN_ID`, `ADMIN_IDS`, `TEST_PREVIEW_ADMIN_IDS`, `STANDARD_OFFER_USER_IDS`, `MAINTENANCE_BYPASS_USER_IDS` и `MAINTENANCE_OFFER_USER_IDS` в `.env`.

Суффиксы `2` и `3` доступны всем пользователям с активным доступом к боту, наличие Premium не требуется. Суффикс `2` запрашивает rich-формат; если Telegram его не принимает, бот отправляет обычный офер. Суффикс `3` отправляет карточку в стиле `/test2`: при Premium используются настроенные эмодзи, без Premium — карточка с маркерами. Администратор может настроить эмодзи карточки и кнопок командами `/testemoji` и `/priceemoji`; настройки общие для обоих ботов. Команда `/maintenance on` закрывает оба бота для новых действий пользователей; дополнительные права аккаунтов настраиваются через переменные `MAINTENANCE_BYPASS_USER_IDS` и `MAINTENANCE_OFFER_USER_IDS`. Кнопки уже созданных оферов (принять, закрыть, отметить передачу и подтвердить получение) продолжают работать. Команда `/maintenance off` снова открывает доступ. Режим общий для бесплатного и платного ботов и сохраняется после перезапуска.

После отметки продавца покупатель подтверждает получение NFT в личном чате с ботом. После подтверждения сделка отмечается как завершённая, а администратор получает уведомление для отдельного расчёта.

Инструкция с примерами для покупателей находится в [BUYER_MANUAL.md](BUYER_MANUAL.md).


## Запуск

1. Укажите `BOT_TOKEN` в `.env`.
2. Выполните `pip install -r requirements.txt`.
3. Запустите `python bot.py`.

## Отдельный платный бот

Для второго экземпляра укажите `PAID_BOT_TOKEN` и `XROCKET_API_TOKEN` в `.env`, затем запустите `python paid_bot.py`. Он использует отдельную базу в `data_paid/`, открывает доступ после разовой оплаты 1 TON через xRocket Pay и не проверяет обязательную группу. После принятия офера продавец получает кнопку `tg://send_gift` для передачи NFT покупателю.

## Автозапуск в окружении

В `.env.example` добавлены настройки главного бота: `MASTER_BOT_TOKEN` и `MANUAL_URL`. Скопируйте пример в `.env`, заполните токен главного бота и при желании ссылку на руководство. Токены дочерних ботов хранятся зашифрованными в `data/master_bots.sqlite3`; ключ шифрования автоматически создаётся в `data/master_bot.key`. Сохраните оба файла: без ключа сохранённые токены нельзя расшифровать.

В настройках главного бота в мини-приложении @BotFather включите **Bot Management Mode**. Без этого Telegram не разрешит пользователям создавать дочерние боты. При создании Telegram сам показывает пользователю форму имени и username; токен передаётся главному боту через Bot API и не запрашивается у пользователя.

Главное меню даёт создать бесплатного или платного бота. Бесплатный профиль использует проверку обязательной группы. В платном профиле пользователь каждого созданного бота оплачивает доступ по действующему тарифу 1 TON через xRocket. Разрешение именно на создание платного профиля администратор главного бота выдаёт командами `/paid_access ID` и отзывает командой `/paid_noaccess ID`. Пользователь может посмотреть свои боты командой `/mybots`, администратор — общий список командой `/bots`. Команда `/token_reset BOT_ID` отзывает токен выбранного дочернего бота и перезапускает его на новом токене.

Каждый созданный бот запускается отдельным процессом с собственной базой, сохраняя текущую логику оферов; журнал сделок продолжает приходить на настроенный `ADMIN_ID`. Процессы управляются вместе с главным ботом через `botctl.sh`. При входе в интерактивную оболочку Bash запускаются бесплатный, платный и главный боты (главный — если заполнен `MASTER_BOT_TOKEN`). Статус и управление доступны через `./botctl.sh status`, `./botctl.sh start`, `./botctl.sh stop` и `./botctl.sh restart`.
